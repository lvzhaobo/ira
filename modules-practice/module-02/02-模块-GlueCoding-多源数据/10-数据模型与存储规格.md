# 10 — 数据模型与存储规格

| 属性 | 内容 |
|------|------|
| **模块编号** | M2 |
| **模块名称** | Glue Coding · 多源数据（Wind / 新浪等） |
| **文档包版本** | v1.2 |
| **技术栈** | 前端 React · 后端 Flask · 代码 GitHub |
| **开发方式** | CoPaw + 本模块 Spec |
| **模块侧重** | 多源行情与资讯的采集、清洗、调度与可观测；强调数据管道与失败降级。 |

---

## 1. 概念模型

```
ingest_data_sources 1 ── * ingest_sync_jobs
ingest_sync_jobs 1 ── * ingest_feed_items（可选，见 §2.3）
```

写入 **M1**：`research_messages`（跨模块表，同库时应用层事务；异库则调 M1 内部 API，见 `09` §4）。

---

## 2. 表定义（PostgreSQL）

### 2.1 `ingest_data_sources`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | `UUID` | PK | `sourceId` |
| `name` | `VARCHAR(128)` | NOT NULL | |
| `provider_type` | `VARCHAR(32)` | NOT NULL | wind/sina/mock/… |
| `enabled` | `BOOLEAN` | NOT NULL，默认 true | |
| `config` | `JSONB` | NOT NULL | **非敏感**调度参数；密钥用 `secret_ref` |
| `secret_ref` | `VARCHAR(256)` | NULL | KMS/环境变量键名，**禁止**明文落库 |
| `schedule_cron` | `VARCHAR(64)` | NULL | 可选，与 CoPaw Cron 并存 |
| `last_job_id` | `UUID` | NULL | FK → `ingest_sync_jobs.id` |
| `last_success_at` | `TIMESTAMPTZ` | NULL | 冗余，便于列表 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL | |

**索引**：`(enabled)`；`(provider_type)`。

### 2.2 `ingest_sync_jobs`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | `UUID` | PK | `jobId` |
| `source_id` | `UUID` | NOT NULL，FK | |
| `status` | `VARCHAR(24)` | NOT NULL | 见 `09` §2.2 |
| `mode` | `VARCHAR(16)` | NOT NULL | full/incremental |
| `idempotency_key` | `VARCHAR(128)` | NULL | UNIQUE（`source_id`, `idempotency_key`）非空组合 |
| `stats` | `JSONB` | NULL | `fetched`/`normalized`/`publishedToM1`/`skipped` |
| `errors` | `JSONB` | NULL | 抽样数组 |
| `error_summary` | `TEXT` | NULL | |
| `started_at` | `TIMESTAMPTZ` | NULL | |
| `completed_at` | `TIMESTAMPTZ` | NULL | |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | |

**索引**：`(source_id, created_at DESC)`；`(status)` WHERE `status IN ('queued','running')`。

### 2.3 `ingest_feed_items`（可选 · M1 未联通时缓冲）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `UUID` | PK |
| `job_id` | `UUID` | FK |
| `source_id` | `UUID` | FK |
| `external_ref` | `VARCHAR(256)` | 上游主键，去重用 |
| `normalized_title` | `TEXT` | |
| `normalized_summary` | `TEXT` | |
| `normalized_body` | `TEXT` | |
| `raw_payload_ref` | `TEXT` | OSS 大报文 |
| `published_message_id` | `UUID` | NULL，对应 M1 `research_messages.id` |
| `created_at` | `TIMESTAMPTZ` | |

**唯一**：`(source_id, external_ref)` 可延迟到接入真实源后添加。

---

## 3. OSS 与原始文件

路径建议：`s3://{bucket}/m2/ingest/{source_id}/{job_id}/raw-{seq}.json`  
留存与合规与全项目一致；**PII/行情版权**字段按企业规范脱敏。

## 5. 与 M1 字段映射（写入 `research_messages` 时）

| `research_messages`（M1） | 来源 |
|----------------------------|------|
| `title` / `summary` / `body` | `ingest_feed_items.normalized_*` 或内存映射 |
| `source_type` | `provider_type` 或归一化枚举 |
| `source_name` | `ingest_data_sources.name` |
| `source_system` | 固定 `glue` 或可配置 |
| `external_ref` | `external_ref` |
| `published_at` | 资讯时间或 `now()` |
| `metadata` | 可放 `jobId`、`batchId` |
