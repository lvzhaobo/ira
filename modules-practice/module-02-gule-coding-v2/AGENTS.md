# AI Agents 协作规范 - Glue Coding 范式

## 🎯 核心理念

**Glue Coding（胶水编程）**：AI 作为主程序员，优先**参考、复用、组合**已验证的成熟代码，而非从零生成。人类负责描述意图、审查结果、把握方向。

### 三大原则
1. **先抄后改** - 永远从参考代码开始，而不是凭空创造
2. **胶水连接** - AI 负责连接和适配已有组件，而非重新发明轮子
3. **样式优先** - 视觉和交互风格必须参考现有实现

## 🛠️ 代码生成工作流

### 第一步：明确需求
- 理解用户想要做什么（功能、页面、组件）
- 确认目标风格方向（企业风？漫画风？数据看板？）

### 第二步：寻找参考（必须执行）
```
1. 检查 my-style/ 是否有客户自定义规范
   - 如果有 → 优先遵循客户风格
   - 如果没有 → 进入下一步

2. 在 reference/ 中匹配最接近的实现
   - 企业后台/管理系统 → reference/solution-prototype/
   - 漫画/创意/办公室场景 → reference/ai-town/
   - 数据看板/图表 → reference/bi/
   - 报告/文档 → reference/report-html/
   - 动画/交互效果 → reference/visual/

3. 阅读参考代码的关键部分
   - HTML 结构组织方式
   - CSS 变量定义（颜色、字体、间距）
   - 组件实现模式
   - 交互逻辑实现
```

**若无高度匹配的参考**：在同一分类中选最接近的 HTML 作骨架再改；全新形态时优先在 `reference/` 落一份可复用模板，避免一次性页面散落。客户已在 `my-style/` 定义的，以规范为准，参考文件主要提供结构与交互范式。

**产出位置**：新建或大幅改编的 HTML/静态资源默认写入 **`output/`**（可按项目建子目录，如 `output/项目名/`）。从 `reference/` 复制后请在 `output/` 中编辑，**不要直接覆盖 `reference/` 下的参考文件**，便于升级参考库与对比差异。

**版权与溯源**：`reference/` 内页面可能含第三方 CDN 脚本/字体或演示用途素材；**对外发布或商用前**请自行核对许可协议。建议在交付物顶部或首个 `<!-- -->` 注释中注明：骨架来源（如 `reference/report-html/workshop-next-steps.html`）、生成日期与主要改动说明；若保留 Chart.js 等库，请保留其版权与许可说明，勿删除上游要求的署名或许可文本。

### 第三步：胶水式生成
```
✓ 复制参考代码的结构骨架
✓ 替换内容、文案、数据
✓ 调整样式变量（颜色、字体等）
✓ 用"胶水代码"连接各组件
✗ 不要从零写 HTML/CSS/JS
✗ 不要凭空创造交互模式
✗ 不要忽略参考代码的设计决策
```

### 第四步：客户风格适配
```
如果 my-style/ 中有定义：
  - 覆盖颜色变量
  - 替换字体规范
  - 调整组件样式
  - 遵循特殊要求

如果 my-style/ 为空：
  - 告知客户可以在此定义风格
  - 使用 reference 中的风格作为默认
```

## 🎨 my-style/ 客户风格定义指南

新客户请先阅读 **`my-style/README.md`**（三步上手：读本规范、按需建风格文件、指定产出到 `output/`）。

客户可以在 `my-style/` 目录下创建以下文件来定义自己的风格：

### 示例文件结构
```
my-style/
├── README.md              # 新客户引导（已提供，可按需补充链接与示例）
├── style-guide.md         # 视觉规范文档
├── colors.css             # 品牌色定义
├── components-spec.md     # 组件要求
└── requirements.md        # 特殊需求说明
```

### style-guide.md 示例内容
```markdown
# 客户风格指南

## 品牌色
- 主色: #XXXXXX
- 辅色: #XXXXXX
- 背景色: #XXXXXX

## 字体
- 标题字体: XXX
- 正文字体: XXX
- 字号规范: ...

## 组件风格
- 按钮: 圆角/直角、阴影、渐变...
- 卡片: 边框、间距、hover 效果...
- 导航: 位置、样式、交互...

## 特殊要求
- 必须使用 XXX 布局
- 禁止使用 XXX 效果
- 参考网站: XXX
```

## 📋 Reference 参考库索引

从选文件到写入 `output/` 的**完整示例与迷你场景**见 **`reference/README.md`**（与下文索引配合使用：索引负责「有哪些文件」，README 负责「怎么抄」）。

### 2. solution-prototype/ - 企业原型风格
**适用场景**: 管理后台、企业应用、产品原型

### 4. report-html/ - 报告文档风格

## ✅ 检查清单

生成代码前必须确认：

- [ ] 已检查 `my-style/` 是否有客户规范
- [ ] 已在 `reference/` 中找到匹配的参考代码
- [ ] 已阅读参考代码的 CSS 变量定义
- [ ] 已理解参考代码的结构组织
- [ ] 准备基于参考代码进行修改（而非从零开始）
- [ ] 已明确新文件写入 `output/`（或团队约定的其他目录），不覆盖 `reference/` 原件

生成代码后必须确认：

- [ ] 样式风格与参考代码一致（或符合 my-style 规范）
- [ ] 代码结构清晰、可维护
- [ ] 交互逻辑完整、无 bug
- [ ] 响应式设计正常工作
- [ ] 告知客户可以在 `my-style/` 中自定义风格
- [ ] 若对外分发：已核对第三方库/素材版权，并在页面中保留要求的声明与溯源注释（见上文「版权与溯源」）
