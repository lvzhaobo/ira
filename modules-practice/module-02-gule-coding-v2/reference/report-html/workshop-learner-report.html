3-Month Advancement Roadmap

3 个月路线图：从"学过"到"能交付"

路线图分为三个阶段——内化（0–4 周）、实战（5–8 周）、沉淀（9–12 周）。 每个阶段有明确的里程碑和衡量标准，帮助你将 Workshop 所学转化为真实项目能力。

阶段一 · Week 1–4 · 内化与配置
将 Workshop 所学落地到当前项目
① 为你负责的项目配置第一套 .qoder/rules/ 文件（参考 BestBuy、卡塔尔航空案例的 Rules 模板）； ② 启动 RepoWiki 对项目进行全量扫描，生成技术地图； ③ 用 Plan 模式对一个真实需求生成 PRD 草稿，邀请同事用开发/合规/UX 三视角评审； ④ 封装 1 个高频 Prompt 为 Command（如代码 Review、API 文档生成）。
里程碑：项目有 Rules 文件，完成 1 次 AI 辅助 PRD 交付
阶段二 · Week 5–8 · 实战深化
在真实客户交付中使用 Qoder 全链路
① 按角色深化：开发——完成 AI 辅助 TDD + Code Review 完整流程；PM——AI 生成高管汇报材料（参考 Lab-A4）；架构师——完成 Lab-A1 技术尽调输出； ② 选择 1 个 Workshop 客户案例中最相关的行业（航空/金融/零售），深入研究对应合规框架，完善 Rules 文件； ③ 在项目 Sprint Retro 中分享一次 Qoder 使用技巧，记录团队反馈； ④ 尝试用 多 Agent 协同处理一个复杂任务（如：尽调报告 + PRD + 测试用例同步生成）。
里程碑：AI 辅助代码率提升 ≥ 20pp，客户交付用上 Qoder 至少 2 个场景
阶段三 · Week 9–12 · 沉淀与传播
把个人经验变成团队资产
① 整理 2–3 个 可复用 SKILL 文件（适用于你所在行业的最佳实践模板），提交到团队 Rules 共享库； ② 设计团队级 AI ROI 度量看板——参考 Workshop 中 Lab-A8 效能治理，记录研发周期缩短率、Bug 逃逸率变化； ③ 在团队内做一次 15 分钟内训分享（1 个真实案例 + Qoder 操作演示 + Rules 文件展示）； ④ 如有条件，为客户出具一份 Lab-A6 深化交付方案，建议二期立项。
里程碑：团队共享 ≥1 套 SKILL，输出至少 1 份可交付的客户 AI 建议报告
阶段四 · Week 13+ · 持续进阶（按兴趣）
MCP 自定义工具 · RAG 知识库 · Agent 编排（视项目需要）
进入 AI 应用开发技术栈（Lab T1–T5）：MCP 工具集成、SKILL 高阶封装、Agent 多跳推理、RAG 企业知识库构建。 这一阶段是可选的，适合有技术交付背景且对 AI 原生应用感兴趣的学员。

Quick Wins · This Week

下周就能做的 5 件事

不需要等待下一次培训——以下 5 个行动，在你当前的项目中就能立即落地，每个都在 2 小时以内完成，但每一个都能让你在客户面前更有底气。

1
为你的项目创建第一个 Rules 文件（30 分钟）最高价值
在项目根目录创建 .qoder/rules/project-rules.md，写入：技术栈约定（禁止/必须的库）、命名规范、安全红线（禁止上传客户敏感数据）。 参考：Workshop 中 BestBuy、卡塔尔航空的 Rules 配置示例。
2
对一个现有函数用 Qoder 补全测试用例（45 分钟）立竿见影
选择项目中一个 10–50 行的业务函数，要求 Qoder 生成：正常路径 + 3 个边界值 + 2 个异常处理测试。 人工验证所有断言是否符合业务逻辑（这是责任归属原则的体现）。
3
用 RepoWiki 扫描项目并设计"暗桩验证"（1 小时）推荐
对你负责的项目启动 RepoWiki，然后设计 2 个你明确知道答案的问题（如"XX 模块用了哪个框架版本"）， 验证 AI 是否真正读了代码而非猜测。对比开/关 @RepoWiki 的回答差异。
4
把一个重复性 Prompt 封装为 Command（30 分钟）推荐
找到你这周用 Qoder 反复发的一个 Prompt（如"帮我 Review 这段代码并检查安全漏洞"）， 封装到 .qoder/commands/ 目录，变成可复用 Command。之后一个 slash 命令搞定。
5
向队友分享 1 个 Qoder 使用技巧（15 分钟）文化传播
在团队 Standup 或企业微信群分享 1 个你在 Workshop 中学到的最有用的 Qoder 用法，配 1 张截图。 知识传播 = 你在团队中影响力的放大器。

Qoder 四条原则
1️⃣ 责任归属：AI 是副驾驶，你是飞行员。提交代码必须完全理解。
2️⃣ 批判性思维：永远不要盲信 AI 首次输出，特别是合规与边界逻辑。
3️⃣ 粒度控制：接口定义 → 核心逻辑 → 测试，三步走，不一锅端。
4️⃣ 知识资产化：好用的 Prompt → Command/Rule → 团队共享资产。

Qoder Feature Quick Reference

Qoder 核心功能：一张纸全掌握

Workshop 涉及的 Qoder 四大核心机制——Rules（约束注入）/ SKILL（能力封装）/ MCP（工具集成）/ RepoWiki（知识索引）。掌握这四个，你就能完成 80% 的企业级 AI 交付场景。

① Rules — 业务约束注入

核心机制
文件位置.qoder/rules/*.md
触发方式对话自动加载，无需 @ 调用
作用范围所有代码生成请求
典型用途技术栈约定 / 命名规范 / 合规红线
Workshop 示例eu261-rules.md · bestbuy-retail.md
示例：eu261-rules.md
# 航空延误赔付规则
- 赔付金额必须引用 EC 261/2004 Art.7
- 所有决策必须记录 decision_id 审计日志
- 禁止重复赔付，必须做 幂等检查
- GDPR Art.9 健康数据不得明文存储

② SKILL — 可复用能力封装

核心机制
文件位置.qoder/skills/*.md
触发方式/skill-name slash 命令调用
与 Rules 区别主动调用 vs 被动注入
典型用途PRD生成 / 代码Review / 测试生成
团队价值个人技巧 → 团队共享资产
示例：gen-prd.md
# PRD 生成 SKILL
description: 从需求描述生成 GWT + PRD
steps:
  1. 识别业务场景和用户角色
  2. 生成 3-5 条 GWT 验收条件
  3. 输出 MoSCoW 优先级需求表

③ MCP — 外部工具集成

核心机制
全称Model Context Protocol
作用让 Qoder 调用外部工具（DB/API/文件）
Workshop 示例Figma MCP（Noli）· 高德地图 MCP
配置方式settings.json 中注册 MCP Server
适用角色技术架构师 / 高级开发顾问

④ RepoWiki — 代码知识索引

核心机制
作用全量扫描代码库，建立知识索引
调用方式@RepoWiki 在对话中引用
Workshop 示例空客中国 12 万行扫描 → 47 分钟
典型用途技术尽调 / 遗留系统理解 / 重构
验证技巧"暗桩验证"：问已知答案验真实性
四大机制协作关系
① RepoWiki 扫描项目，建立代码知识库
② Rules 自动注入业务约束，驱动合规代码生成
③ SKILL 封装可复用流程，主动触发执行
④ MCP 接入外部系统，扩展 Qoder 感知边界
给初学者的建议：从 Rules 开始
四个机制里，Rules 是投入产出比最高的起点——30 分钟写一个 .md 文件，立即改善所有代码生成的质量和合规性。 SKILL 其次，把你反复用的 Prompt 流程化。MCP 和 RepoWiki 适合有经验后再深入。

如何转化为 Rules 文件
1. 选择你所在行业的合规框架
2. 把"关键约束"列的每一条复制到 .qoder/rules/ 对应的 .md 文件
3. 用自然语言描述禁止/必须的行为
4. 测试：让 Qoder 生成相关功能，检查是否遵循约束
合规 ≠ 负担

不只是写代码，是写合规的代码。
