Quick Wins · This Week

下周就能做的 5 件事

不需要等待新的培训机会——以下 5 个行动，在你当前的项目中就能立即落地，每个都在 2 小时以内完成，但效果立竿见影。

快速落地行动清单（建议下周完成）
Action 1：为你的项目创建第一个 Rules 文件（30 分钟）最高价值
在项目根目录创建 .qoder/rules/project-rules.md，写入：技术栈约定（禁止的库/必须的库）、命名规范、安全红线（禁止上传的内容）。
参考：查看 BestBuy 案例中的 bestbuy-retail.md Rules 示例
Action 2：对一个现有函数用 Qoder 补全测试用例（45 分钟）立竿见影
选择项目中一个 10–50 行的业务函数，要求 Qoder 生成：正常路径 + 3 个边界值 + 2 个异常处理测试。人工验证所有断言是否符合业务逻辑（这一步是责任归属的体现）。
Action 3：做一次 RepoWiki 扫描并设计"暗桩验证"（1 小时）推荐
对你负责的项目启动 RepoWiki，然后设计 2 个你明确知道答案的问题（如"XX 模块用了哪个框架版本"），验证 AI 是否真的读了代码而非猜测。对比开/关 @RepoWiki 的回答差异。
Action 4：把一个重复性 Prompt 封装为 Command（30 分钟）推荐
找到你这周用 Qoder 反复发的一个 Prompt（如"帮我 Review 这段代码并检查安全漏洞"），封装到 .qoder/commands/ 目录，变成一个可复用的 Command。之后一个 slash 命令搞定。
Action 5：向队友分享 1 个 Qoder 使用技巧（15 分钟）文化传播
在团队 Standup 或者 Slack 里分享 1 个你在 Workshop 中学到的最有用的 Qoder 用法，配 1 张截图。知识传播 = 你影响力的放大器。
原则 1：批判性思维

永远不要盲目信任 AI 首次生成的代码。特别关注：最新 API / 边界条件 / 合规逻辑。Rules 文件是你对抗 AI 幻觉最有效的工具。

原则 2：粒度控制

不要让 AI 一次性生成整个模块。拆解为：接口定义 → 核心逻辑 → 测试用例三步走。每步都人工验证，才能保持对代码的掌控力。

原则 3：责任归属

"这是 AI 写的，bug 不怪我"——这句话在埃森哲项目中不成立。你提交的代码必须完全理解并负责，AI 只是副驾驶。

原则 4：知识资产化

每次你花 30 分钟摸索出一个好用的 Prompt 或 Rule，把它写进 Rules 或 Command 文件。个人技巧 → 团队共识 → 组织 AI 资产。
