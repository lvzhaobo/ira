本页面用于帮助项目团队快速理解：当分布式系统发生 网络分区 时，系统为什么往往需要在 一致性（Consistency） 和 可用性（Availability） 之间做出取舍。

1. 选择网络环境 Partition Tolerance 永远必须要有（P）
2. 网络分区时的策略（CAP 取舍） 只能二选一：C + P 或 A + P
3. 模拟请求 请求会持续自动发送，你也可以手动触发

如何理解这张图：
- 左侧是客户端，右侧是 3 个副本节点（A / B / C），中间的虚线代表网络分区。
- 当“无网络分区”时，系统可以既一致又可用。
- 当“发生网络分区”时：
  · 如果选择 CP，孤立分区会拒绝请求（保证数据不会脏读，但有不可用）。
  · 如果选择 AP，孤立分区仍然响应请求（系统更可用，但可能读到旧数据）。
