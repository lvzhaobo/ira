# 验收清单与测试用例（TC）：知识库与问答 · CoPaw 底座

> **版本**：v0.1  
> **日期**：2026-04-03  
> **依据（三段式）**：`00-Proposal`（范围已评审）→ **`01-Spec` 冻结版**（契约基准）→ 本文 TC  
> **说明**：本环节以 **可演示 + 可勾选** 为主；自动化测试为可选。验收时 **AC/TC 仅对照已冻结的 Spec 版本**（见 `01` 文首状态与版本号）。

## 1. P0 验收清单（发布前必勾）

| ID | 验收项 | 通过标准 | 对应 Task |
|----|--------|----------|----------|
| AC-01 | 文档列表 | `GET /kb/documents` 返回 200，`items` 为数组（可为空） | T-B |
| AC-02 | 索引状态 | `GET /kb/index/status` 返回 200，含 `index_ver`、`updated_at`、`status` | T-B |
| AC-03 | 上传成功 | `POST /research/qa/upload` 成功时返回 `doc_id`、`trace_id` | T-C |
| AC-04 | 列表可见 | 上传后再次 `GET /kb/documents` 含新 `doc_id`（或演示说明延迟策略） | T-C |
| AC-05 | 问答结构 | `POST /research/qa/ask` 返回含 `answer`、`evidence_refs`、`trace_id` | T-D |
| AC-06 | 无证据拒答 | 无命中材料时 `evidence_refs=[]`，`answer` 为拒答模板，`compliance.decline_reason` 可测 | T-D |
| AC-07 | CoPaw Skill | Skill 能调通 `POST /research/qa/ask` 并展示结果（演示录屏或截图即可） | T-F |
| AC-08 | trace 一致 | 同一会话演示中 `trace_id` 可解释（与血缘/日志二选一即可） | T-D, T-C |

## 2. 测试用例（TC）

| TC 编号 | 场景 | 步骤摘要 | 期望 | 对应 AC | 对应 Task |
|---------|------|----------|------|---------|----------|
| TC-01 | 空库列表 | 调用 `GET /kb/documents` | 200，`items=[]` 或等价 | AC-01 | T-B |
| TC-02 | 上传 PDF | multipart 上传小文件 | 200，`doc_id` 非空 | AC-03 | T-C |
| TC-03 | 列表含新文档 | 上传后 `GET /kb/documents` | `items` 中存在对应 `doc_id` | AC-04 | T-C |
| TC-04 | 正常问答 | `ask` 带与材料相关的 `query` | `answer` 非空；`evidence_refs` 结构符合 Spec | AC-05 | T-D |
| TC-05 | 无材料问答 | `query` 与库无关或检索为空 | `evidence_refs=[]`，拒答文案出现 | AC-06 | T-D |
| TC-06 | 错误上传 | 空文件或超大文件 | 4xx，错误体含 `error` | AC-03 | T-C |
| TC-07 | Skill 路径 | 在 CoPaw 触发 Skill | HTTP 到达 BFF，响应可解析 | AC-07 | T-F |
