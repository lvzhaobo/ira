# 10 — 数据模型与存储规格

| 属性 | 内容 |
|------|------|
| **模块编号** | M5 |
| **模块名称** | Qoder Experts · 多 Agent 论股基 |
| **文档包版本** | v1.2 |
| **技术栈** | 前端 React · 后端 Flask · 代码 GitHub |
| **开发方式** | CoPaw + 本模块 Spec |
| **模块侧重** | 多角色 Agent 辩论、工具白名单、纪要导出与合规免责声明。 |

---

## 1. 概念模型与关系

```
users 1 ── * debate_sessions
debate_sessions 1 ── * debate_utterances
debate_utterances 1 ── * debate_tool_calls
debate_sessions 1 ── 0..1 debate_export_artifacts（可按需仅走 OSS，不建表）
```

- **`agent_id`** 枚举与 `06` §1 一致：`M5-BULL` | `M5-BEAR` | `M5-MOD`（+ P1 `M5-MACRO`）；**不得**存编排器伪 ID。  
- 全局 `chats` / `chat_messages` 若存在：`debate_sessions.chat_id` 可选外键，便于在统一会话列表中挂载本模块会话。

---

## 2. 表定义（PostgreSQL 建议）

命名前缀 `debate_` 便于与兄弟模块表区分；可按团队规范改为 `m5_` 前缀，**字段语义保持不变**。

### 2.1 `debate_sessions` — 辩论会话

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | `UUID` | PK，默认 `gen_random_uuid()` | 对外即 `09` 中 `sessionId` |
| `user_id` | `UUID` / `BIGINT` | NOT NULL，FK → `users.id` | 属主 |
| `chat_id` | `UUID` | NULL，FK → `chats.id` | 与全局 Chat 对齐时填写 |
| `topic` | `TEXT` | NOT NULL | 用户议题/问题陈述 |
| `symbol` | `VARCHAR(32)` | NULL | 标的代码，如股票/基金代码 |
| `symbol_type` | `VARCHAR(16)` | NULL | 枚举：`STOCK` / `FUND` / `INDEX` / `OTHER` |
| `title` | `VARCHAR(200)` | NULL | 列表展示用摘要标题，可后算写入 |
| `status` | `VARCHAR(24)` | NOT NULL，默认 `draft` | 见 §2.5 |
| `max_rounds` | `INT` | NOT NULL，默认 `4` | 多空来回上限（不含 `M5-MOD` 收尾轮时可单独策略） |
| `agent_profiles` | `JSONB` | NOT NULL，默认 `{}` | 每 Agent 的 profile / 模型参数，见 §3 |
| `orchestrator_state` | `JSONB` | NULL | 编排器内部：下一发言者、已执行轮次等，**勿暴露给前端细粒度** |
| `disclaimer_version` | `VARCHAR(32)` | NOT NULL | 免责声明模板版本 |
| `idempotency_key` | `VARCHAR(128)` | NULL，UNIQUE（`user_id`, `idempotency_key`）非空时 | 与 `09` 创建会话幂等 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | 触发器维护 |
| `completed_at` | `TIMESTAMPTZ` | NULL | `status=completed` 时写入 |

**索引**：`(user_id, created_at DESC)`；可选 `(chat_id)`。

### 2.2 `debate_utterances` — 单次专家发言

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | `UUID` | PK | 对外 `utteranceId` |
| `session_id` | `UUID` | NOT NULL，FK → `debate_sessions.id` ON DELETE CASCADE | |
| `seq` | `INT` | NOT NULL | 会话内严格递增，从 1 起；**展示顺序以此为准** |
| `round_no` | `INT` | NOT NULL | 辩论轮次（1 起）；同一 `round_no` 可有 BULL 再 BEAR |
| `agent_id` | `VARCHAR(32)` | NOT NULL | `M5-BULL` / `M5-BEAR` / `M5-MOD` / … |
| `content` | `TEXT` | NOT NULL | 主文本，建议 Markdown |
| `content_format` | `VARCHAR(16)` | NOT NULL，默认 `markdown` | 预留 `plain` |
| `structured` | `JSONB` | NULL | 可选：要点列表、对比表机器可读片段 |
| `model_name` | `VARCHAR(64)` | NULL | 实际调用的模型名 |
| `prompt_version` | `VARCHAR(32)` | NULL | 系统提示版本，审计用 |
| `finish_reason` | `VARCHAR(24)` | NULL | 如 `stop` / `length` / `error` |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | |

**唯一约束**：`(session_id, seq)` UNIQUE。  
**索引**：`(session_id, seq)`。

### 2.3 `debate_tool_calls` — 工具调用（溯源 / 审计）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | `UUID` | PK | |
| `utterance_id` | `UUID` | NOT NULL，FK → `debate_utterances.id` ON DELETE CASCADE | 归属哪条发言 |
| `session_id` | `UUID` | NOT NULL，FK → `debate_sessions.id` | 冗余，便于按会话查 |
| `agent_id` | `VARCHAR(32)` | NOT NULL | 与发言一致，审计 |
| `tool_name` | `VARCHAR(64)` | NOT NULL | 如 `m2.quote_snapshot` / `m3.search_chunks` |
| `request_payload` | `JSONB` | NOT NULL | 请求参数（脱敏后入库） |
| `response_status` | `VARCHAR(16)` | NOT NULL | `ok` / `error` |
| `response_summary` | `TEXT` | NULL | 列表展示用短摘要 |
| `response_payload_ref` | `TEXT` | NULL | 大响应存 OSS 时的 object key |
| `citation_refs` | `JSONB` | NULL | `[{ "type":"chunk","id":"..."}]` 等与 M3/M2 对齐 |
| `latency_ms` | `INT` | NULL | |
| `error_code` | `VARCHAR(64)` | NULL | 与 `09` 业务码可映射 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL，默认 `now()` | |

**索引**：`(session_id, created_at)`；`(utterance_id)`。

### 2.4 `debate_export_artifacts`（可选）

若导出走异步任务或大文件，建议独立表；同步直接返回 Markdown 时可不建。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `UUID` | PK |
| `session_id` | `UUID` | FK |
| `format` | `VARCHAR(16)` | `markdown` / `pdf` |
| `storage_uri` | `TEXT` | OSS 路径或内联标记 |
| `checksum` | `VARCHAR(64)` | 完整性 |
| `created_at` | `TIMESTAMPTZ` | |

## 3. JSONB：`agent_profiles` 形状（与 `09` 请求对齐）

```json
{
  "M5-BULL": { "profile": "default", "prompt_version": "2026-04-04", "temperature": 0.3 },
  "M5-BEAR": { "profile": "default", "prompt_version": "2026-04-04", "temperature": 0.3 },
  "M5-MOD":  { "profile": "summary_only", "prompt_version": "2026-04-04", "temperature": 0.2 }
}
```

- 未出现的 Agent key 表示使用服务端默认 profile。  
- **`profile`**：运营配置键，**不**产生新 `agent_id`（`06` §1.4）。

---

## 4. `status`（`debate_sessions.status`）

| 值 | 含义 |
|----|------|
| `draft` | 已创建，尚未产生任何 utterance |
| `in_progress` | 辩论进行中 |
| `completed` | 编排判定结束（含 MOD 收尾） |
| `failed` | 不可恢复错误（如连续模型失败） |
| `archived` | 用户或策略归档 |

---

## 5. 存储与合规

| 项 | 建议 |
|----|------|
| RDS | 与全项目同一 PostgreSQL 实例；本模块独立 schema 可选 `debate` |
| OSS | `tool` 大响应、`pdf` 导出：`s3://{bucket}/m5/debate/{session_id}/...` |
| TTL | 会话与 utterance 保留策略与合规一致；删除会话级联删除子表 |
| PII | `request_payload` 入库前脱敏；日志禁止完整 query 明文（与 `07` 一致） |

---

## 6. 与 `09` 对齐检查清单

- API 中 `sessionId`、`utteranceId`、`seq`、`roundNo`、`agentId` 与上表字段一一对应（驼峰 ↔ snake）。  
- 列表/详情 DTO 字段子集须为表字段投影，避免前端依赖未持久化字段。
