## 1. 多 Agent 角色定义（投研助手 · 实现前须对齐）

本节为本模块的**单一事实来源（SSOT）**：编排、提示词、工具白名单、前端展示名与审计字段均须与下表 **Agent ID** 一致；变更须走本模块修订与追踪流程（见 `01` §4、`14`），并递增提示词/API 版本号。

### 1.1 设计原则

- **人机边界**：多 Agent 仅辅助信息整理与观点对照，**不构成投资建议**，不替代合规与投委会决策。
- **可溯源**：凡引用行情、新闻、研报片段，须标注来源（工具回执 ID / chunk ID / 时间戳）；无依据须明确拒答或标为「模型推断」。
- **工具最小化**：每 Agent 仅允许 `11` 中登记的白名单工具；默认 **只读**，禁止下单、改仓、代客操作类工具。
- **P0 / P1**：P0 为「双观点 + 纪要官」三角色闭环；P1 可增第三专业视角（如宏观）或延长轮次，不改变 P0 角色 ID 语义。

### 1.2 角色总表（P0）

| Agent ID | 对用户展示名 | 角色定位 | 论证立场 | 典型输出 | P0 允许工具（示例） | 显式禁止 |
|----------|--------------|----------|----------|----------|---------------------|----------|
| `M5-BULL` | 看多研究员 | 从成长与催化剂角度补充论据 | 建设性、偏乐观但需可反驳 | 分点观点 + 依据引用 + 风险提示（自身立场局限） | 只读行情（M2 契约）、内部检索（M3） | 编造数值/新闻；承诺收益；诱导交易 |
| `M5-BEAR` | 风控 / 看空研究员 | 从估值与下行风险角度质疑 | 质疑性、偏谨慎 | 风险清单 + 依据引用 + 对看多论据的针对性回应 | 同左 | 同左 |
| `M5-MOD` | 辩论主持 / 纪要官 | **不站队**；结构化归纳与分歧标注 | 中立 | 观点对照表、共识 / 分歧点、待用户核实项、免责声明块 | 无工具或仅「格式化 / 摘要」类（不得拉取新行情作结论依据） | 输出最终买卖建议；替用户做决策；虚构双方未讨论的内容 |

**会话角色实例**：一次辩论会话内，编排层为每个 Agent ID 各绑定 **一条** 运行配置（模型 profile、温度、系统提示版本）；同一 ID 在多会话间配置可不同，但 **ID 语义不变**。

### 1.3 与编排层、系统组件的边界

| 组件 | 是否「Agent」 | 说明 |
|------|----------------|------|
| 编排器 / 路由（Orchestrator） | **否** | 负责轮次、调用顺序、超时与重试；不写进「辩论发言」角色表 |
| `M5-BULL` / `M5-BEAR` / `M5-MOD` | **是** | 对用户可见或可审计的「专家角色」，须独立系统提示与工具策略 |
| 全局 Chat Shell | **否** | UI 与会话容器；继承全局会话模型，但不等同于某一 Agent |

### 1.4 P1 扩展（可选，实施时单独 REQ）

| Agent ID（预留） | 对用户展示名 | 用途 |
|------------------|--------------|------|
| `M5-MACRO` | 宏观 / 流动性观察员 | 在用户显式开启时加入第 4 视角；须独立工具白名单与免责声明 |

同一 Agent ID 下若需多套提示词/模型参数，用配置字段 **`profile`**（或等价名）区分，**不**为此发明新的 `agent_id`。

### 1.5 与 `05` / `09` / `11` 的映射

- 用户故事与 AC 中凡涉及「多 Agent」，应引用 **Agent ID** 或上表展示名。  
- **接口与持久化**：REST 侧 DTO（驼峰）与表字段（蛇形）对照见 **`09` §2～§3**、**`10` §2～§6**。  
- `09` 中会话、轮次、发言须带 `agentId` / 库表 `agent_id`，枚举 ⊆ 本节表。  
- `11` 中工具白名单按 **Agent ID** 分列维护。
