## 1. 愿景与目标

在基金投研场景下，交付 **Qoder Experts · 多 Agent 论股基**，使用户在合规前提下提升信息获取与决策辅助效率。

## 2. 角色与权限（概要）

| 角色 | 能力 |
|------|------|
| 投研用户 | 使用本模块面向用户的功能 |
| 运营/数据 | 配置与监控（若本模块包含） |
| 管理员 | 用户与权限（引用全局 05a / `11`） |

## 2.1 投研多 Agent 角色概要（人类用户 vs 对话 Agent）

> **完整定义（Agent ID、工具边界、禁止项）以 `06` §1 为唯一事实来源。**

| Agent ID | 展示名（用户可见） | 一句话 |
|----------|-------------------|--------|
| `M5-BULL` | 看多研究员 | 从成长与催化剂角度给出建设性论据，须可溯源。 |
| `M5-BEAR` | 风控 / 看空研究员 | 从估值与风险角度质疑，须可溯源。 |
| `M5-MOD` | 辩论主持 / 纪要官 | 中立归纳、输出对照表与分歧点，**不提供买卖结论**。 |

P0 辩论闭环 = 上述三者 + 编排器（编排器不是对话 Agent，见 `06` §1.3）。

## 3. 核心业务场景（3～5 条，实施时补全）

1. （主场景）用户给定标的或议题 → `M5-BULL` / `M5-BEAR` 多轮观点交锋（只读工具）→ `M5-MOD` 输出结构化纪要 + 免责声明；全程可追溯依据。  
2. （异常）外部依赖失败时的可理解反馈与重试。  
3. （集成）与兄弟模块的数据/事件衔接场景。

## 4. 验收与成功标准（PRD 层）

- 可演示的端到端路径 + 1～2 个可量化指标（延迟、成功率、准确率等，按模块选）。  
- 细粒度 AC 写在 `05`，此处仅概要并与 `03` 成功标准对齐。
