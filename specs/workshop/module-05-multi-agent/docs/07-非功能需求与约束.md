## 1. 性能与可用性

### 1.1 API 延迟（不含上游 LLM 耗时部分单独拆开）

| 端点（见 `09`） | 目标 | 说明 |
|-----------------|------|------|
| `GET /experts/health` | P95 **≤ 200 ms** | 不依赖外部模型 |
| `POST /experts/sessions` | P95 **≤ 800 ms** | 仅持久化 + 校验 |
| `GET /experts/sessions/{id}` | P95 **≤ 500 ms** | `limit≤50`；随 `limit` 线性放宽至 **≤ 1200 ms**（`limit=200`） |
| `GET .../export?format=markdown` | P95 **≤ 2 s** | 会话 utterance **≤ 200 条** 时 |

### 1.2 单次 `POST .../turn`（含模型与工具）

| 指标 | **staging 目标** | **prod 目标** | 说明 |
|------|------------------|---------------|------|
| 端到端成功返回 P95 | **≤ 90 s** | **≤ 120 s** | 单轮 `mode=step`、含 ≤4 次工具调用场景 |
| 端到端 P99 | **≤ 180 s** | **≤ 240 s** | 超时则返回 `503 M5_MODEL_UNAVAILABLE` 或业务约定错误体，**不得**挂死连接 |
| 单工具调用超时 | **≤ 15 s** | **≤ 15 s** | 单工具；失败计入可观测性 |
| 并发会话（单实例） | **≥ 20** 活跃 turn | **≥ 50** | 超出则 **429** 或排队（须在 `09` 文档声明策略） |

*上述秒级目标依赖模型与 M2/M3 网络；**prod** 以压测报告为准，允许在 `12` M4 门禁前微调 ±20% 并修订本文档版本。*

### 1.3 可用性

| 环境 | 目标 | 口径 |
|------|------|------|
| prod | 月度 **≥ 99.5%** | 本模块 API（`/api/v1/experts/*`）5xx 率与不可用时长；**不含**上游 LLM 厂商 SLA |
| staging | **无硬性 SLO** | 用于逼近 prod 配置与压测 |

### 1.4 降级策略（与 `09` 一致）

- 模型不可用：返回 `503`，`message` 可读；可选提示「稍后重试」。  
- 单工具失败：该轮发言可部分完成并标注工具错误（与 `10` `debate_tool_calls.response_status=error` 一致）。  
- 限流：返回 `429`，附 `Retry-After`（若实现）。

## 2. 安全与合规

- 基金投研：**不产出投资建议承诺**；输出含免责声明，文案版本与 `06` / 会话 `disclaimerVersion` 对齐。  
- 鉴权：所有写路径校验会话属主；敏感字段分级与脱敏规则与全项目一致。  
- **留存**：`debate_sessions` / 关联子表默认保留 **180 天**（可配置）；用户删除请求在 **30 日内** 完成物理删除或不可逆匿名化（与 `10` §5 一致，若冲突以合规评审为准）。

## 3. 可观测性（日志、指标、告警）

### 3.1 日志（必选字段）

每条请求/关键业务日志建议包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `traceId` | string | 与 `09` 错误体 `traceId` 一致 |
| `requestId` | string | 网关或应用生成 |
| `userId` | string | 脱敏展示按平台规范 |
| `module` | string | 固定 `M5` |
| `sessionId` | string | 有则填 |
| `path` | string | 如 `/api/v1/experts/sessions` |
| `durationMs` | number | 请求耗时 |

可与 **阿里云日志服务 SLS** 采集：Logstore 按项目统一，查询分析 SQL 见 §3.4。

### 3.2 指标（建议 Prometheus 命名，SLS 可做等价统计）

| 指标名 | 类型 | 标签（labels） | 说明 |
|--------|------|----------------|------|
| `m5_http_requests_total` | Counter | `method`, `path`, `status` | 全路径 |
| `m5_http_request_duration_seconds` | Histogram | `path` | 桶建议 0.05,0.1,0.25,0.5,1,2,5,15,30,60,120 |
| `m5_turn_total` | Counter | `result`=`ok`/`error` | 每次 `POST .../turn` 结束 |
| `m5_turn_duration_seconds` | Histogram | `mode` | `step`/`run_round`/`finish` |
| `m5_tool_calls_total` | Counter | `tool_name`, `agent_id`, `status` | 与 `10` 一致 |
| `m5_model_errors_total` | Counter | `error_code` | 如限流、超时 |

### 3.3 告警阈值（**量化**，可与 SLS 告警 / 云监控联动）

以下默认针对 **prod**；**连续窗口**指滑动窗口内条件持续成立。

| 告警 ID | 条件 | 严重级别 | 建议动作 |
|---------|------|----------|----------|
| **M5-A1** | `5xx` / (`2xx`+`4xx`) **> 2%**，连续 **5 min** | P2 | 值班群 + 自动工单 |
| **M5-A2** | `POST .../turn` P95 **> prod 目标 120s × 1.5**（即 **> 180s**），连续 **15 min** | P2 | 扩容/切模型/限流 |
| **M5-A3** | `m5_model_errors_total` 增速 **> 50 次/5 min**（按 `error_code` 分组） | P3 | 检查密钥、配额、上游状态 |
| **M5-A4** | `429` 占比 **> 10%** 且持续 **10 min** | P3 | 评估配额与实例数 |
| **M5-A5** | `M5_FORBIDDEN`（403）突增 **> 基线 3 倍** 且 **> 20 次/min** | P3 | 排查扫描或鉴权 bug |

*基线：上线后第 2 周滚动统计；SLS 可用 `status` + `path` 聚合实现 A1/A4。*

### 3.4 SLS 查询示例（占位，按实际 Logstore 字段名替换）

```sql
* | module: M5 
| SELECT path, 
         approx_percentile(durationMs, 0.95) AS p95_ms,
         COUNT_IF(status >= 500) * 100.0 / COUNT(*) AS err_rate_pct
  FROM log
  GROUP BY path
```

告警：对 `err_rate_pct > 2` 订阅钉钉/邮件 Webhook。

### 3.5 与质量门禁（`13`）的关系

- `12` M3 要求黄金用例全绿；**本文件 A1～A5** 为运行期 SLO，不替代 CI。  
- 发版前建议在 staging 跑一轮压测，输出报告附在发布说明（可选模板：`turn` QPS、P95/P99）。

## 4. 阿里云与资源

- 模型：灵积/百炼等；**prod** 须配置独立 RAM 子账号与密钥轮换周期 **≤ 90 天**。  
- 异步导出 PDF（若启用）：FC + MQ；队列积压 **> 1000** 条持续 **30 min** 触发 **P3** 告警。  
- 成本：按 token/调用量做 **日预算**；超预算 **80%** 日报、**100%** 限流或降级（策略由财务与 SRE 共签）。
