# 04 — 产品需求说明（PRD）

| 属性 | 内容 |
|------|------|
| **模块编号** | M2 |
| **模块名称** | Glue Coding · 多源数据（Wind / 新浪等） |
| **文档包版本** | v1.2 |
| **技术栈** | 前端 React · 后端 Flask · 代码 GitHub |
| **开发方式** | CoPaw + 本模块 Spec |
| **模块侧重** | 多源行情与资讯的采集、清洗、调度与可观测；强调数据管道与失败降级。 |

---

## 1. 愿景与目标

将 **多源、异构** 资讯与行情数据 **可靠同步** 到投研侧可读存储（M1 消息池），并具备 **可观测、可重试、可降级**。

## 2. 角色

| 角色 | 能力 |
|------|------|
| 数据工程 | 配置源、触发任务、看日志 |
| 投研用户 | 不直接使用本模块（消费 M1） |
| 管理员 | 密钥与权限 |

## 3. 核心业务场景

1. 运维选择数据源 → 触发增量同步 → 任务成功 → M1 出现新消息。  
2. 上游失败 → 任务 `failed`/`partial` → 错误可定位（traceId、batchHint）。  
3. Mock 源用于 **无合同环境** 演示全链路。

## 4. 验收（PRD 层）

- 至少 **1 个 Mock 源** + **1 次成功任务** + M1 可见 **≥1 条** 对应消息（或缓冲表有记录）。  
- 细粒度 AC 见 `05`。

## 5. 优先级

| 项 | P0 |
|----|-----|
| 源列表、触发任务、任务查询 | ✓ |
| 写 M1 或缓冲表 | ✓ |
| Wind 真连 | P1（合规后） |
