## 输出要求

1. 读取并分析所有目标代码文件
2. 逐条检查每个规则
3. 以严格 JSON 数组格式输出 findings：

```json
[
  {
    "id": "{CATEGORY}-001",
    "category": "{category}",
    "severity": "high|medium|low",
    "file": "文件相对路径",
    "line": "行号或行范围",
    "title": "问题简述（一句话）",
    "description": "详细描述 + 金融场景影响",
    "fix_suggestion": "修复建议"
  }
]
```

## 约束

- 只报告**确实存在**的问题，不要猜测或过度解读
- 每个 finding 必须标明**具体文件和行号**
- severity 按**金融监管影响**评估：high=可能违规/资损，medium=影响体验/运维，low=代码质量
- 规则要**通用化**：描述「模式」而非硬编码特定行号
