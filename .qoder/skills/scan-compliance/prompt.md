# Scan Compliance — 合规风险扫描

> 一句话定义：让 **开发者/安全团队** 在 **代码审查或上线前** 通过 **规则匹配 + 语义分析** 完成 **合规风险点识别与修复建议**

---

## ① 触发条件（WHO）

当用户说以下内容时触发：

- "扫描合规"、"检查敏感词"
- "合规审查"、"合规扫描"
- "compliance scan"
- "/scan-compliance"

---

## ② 什么时候用（WHEN）

### 应该使用

- 代码中涉及投资建议、收益承诺等金融文案
- 上线前合规检查
- PR Review 时辅助扫描
- 营销文案或用户界面文本审查

### 不应使用

- 纯基础设施代码（CI/CD 配置等）
- 已有专业合规团队人工审核流程的最终环节
- 非金融行业项目

---

## ③ 执行步骤（WHAT）

```
1. 收集扫描目标（代码文件 / 文本 / 指定目录）
2. 规则匹配（敏感词库：保本/稳赚/承诺收益等）
3. 语义分析（是否构成投资建议/收益承诺）
4. 生成 findings 报告（JSON 格式）
5. 输出修复建议（替换话术/添加免责声明）
```

### 步骤 1：确定扫描范围

- 默认扫描当前项目所有 `.py`、`.js`、`.ts`、`.md`、`.html` 文件
- 用户可指定文件或目录
- 优先扫描：注释、字符串常量、模板文本、API 响应体

### 步骤 2：敏感词规则库

| 规则 ID | 类别 | 关键词/模式 | 严重度 |
|---------|------|-----------|--------|
| PROMISE_RETURN | 收益承诺 | 保本、稳赚、保证收益、年化收益至少X% | HIGH |
| INVEST_ADVICE | 投资建议 | 建议买入、全仓、加仓、推荐购买 | HIGH |
| MISLEADING | 误导性 | 零风险、绝对安全、必涨 | HIGH |
| MISSING_DISCLAIMER | 缺免责 | 含收益数据但无免责声明 | MEDIUM |
| INFORMAL_RISK | 风险表述不规范 | "风险不大"、"基本没问题" | LOW |

### 步骤 3：语义分析

不只看关键词，还要判断上下文：
- "历史年化收益率 8%"（客观陈述）→ OK
- "年化收益至少 8%"（收益承诺）→ HIGH
- "建议关注该基金"（弱建议）→ MEDIUM
- "建议全仓买入"（强建议）→ HIGH

### 步骤 4：生成报告

每条 finding 包含：文件路径、行号、严重度、规则 ID、原文引用、修复建议。

## ④ 具体实现（HOW）

### 方式 A：集成 ira-tools MCP

如果已启动 ira-tools 后端：

```
调用 ira_compliance_scan 工具
传入参数: text = "待扫描文本"
解析返回: compliant(bool) + violations(list)
```

### 方式 B：纯 Prompt 规则扫描

无需外部服务，直接用上述规则库进行文本匹配 + 语义判断。

## ⑤ 输出格式（FORMAT）

### 正常输出（有发现）

```markdown
## 合规扫描报告

**扫描范围**：[文件/目录列表]
**扫描时间**：[时间]

### 发现汇总

| 严重度 | 数量 |
|--------|------|
| HIGH | 2 |
| MEDIUM | 1 |
| LOW | 0 |

### 详细发现

#### [HIGH] PROMISE_RETURN — 收益承诺

- **文件**：`app/templates/report.html`
- **行号**：42
- **原文**：`保本收益至少20%`
- **建议**：改为 → `历史业绩不代表未来表现，投资有风险`

#### [MEDIUM] MISSING_DISCLAIMER — 缺免责声明

- **文件**：`app/blueprints/research.py`
- **行号**：78
- **原文**：返回收益数据但无免责声明
- **建议**：在响应体中添加 `disclaimer` 字段
```

### 正常输出（无发现）

```markdown
## 合规扫描报告

**结果**：未发现合规风险 ✅
**扫描范围**：[文件列表]
```

### 错误输出

```markdown
## 扫描失败

**错误**：无法读取目标文件
**建议**：检查文件路径是否正确
```

## ⑥ 约束与红线（GUARD）

### 硬性规则

- **不做法律定性判断**，只标记风险点并提供建议
- **不修改代码**，仅输出报告
- 敏感词库需定期更新（随监管政策变化）
- 免责声明文案由合规团队最终确认

### 决策规则

1. 同一行触发多条规则时，取最高严重度
2. 不确定是否构成违规时，标记为 MEDIUM 并附注"建议人工复核"

## 常见错误

### 错误 1：只看关键词不看上下文

**现象**：把"历史年化收益率 8%"也标记为 HIGH
**原因**：关键词匹配没有语义分析
**正确做法**：区分客观陈述（"历史收益率"）和主观承诺（"至少 X%"）

### 错误 2：忽略注释和模板中的敏感文案

**现象**：代码注释里写了"稳赚不赔"作为示例，上线后被监管发现
**原因**：只扫描了正式代码，跳过了注释和模板
**正确做法**：注释、字符串常量、HTML 模板全部纳入扫描范围

### 错误 3：扫描报告没有修复建议

**现象**：开发者看到 HIGH 但不知道怎么改
**原因**：只标记了问题，没有给出替换话术
**正确做法**：每条 finding 必须附带具体修复建议
