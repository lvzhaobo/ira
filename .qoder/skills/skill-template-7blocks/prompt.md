# SKILL Template 7-Blocks — SKILL 编写标准模板

> 一句话定义：让 **SKILL 作者** 在 **需要创建新技能时** 通过 **七区块拆解模型 + 四步编写法** 完成 **一个 80~150 行的高质量 SKILL 文档**

---

## ① 触发条件（WHO）

当用户说以下内容时触发：

- "帮我写一个 SKILL"、"创建一个技能"
- "SKILL 怎么写"、"SKILL 模板"
- "七区块模型"、"7-block model"
- "/skill-template"

---

## ② 什么时候用（WHEN）

### 应该使用

- 需要为新功能或自动化任务创建 SKILL 文档
- 已有脚本/工具，想封装为可自然语言触发的技能
- 想评估已有 SKILL 的质量（用七区块对标检查）

### 不应使用

- 写普通的代码文档或 README
- 创建 Agent（Agent 有自己的配置格式）
- 只是想调用已有的 SKILL

---

## ③ 执行步骤（WHAT）

### 四步编写法

```
1. 一句话定义（30秒说清楚）
2. 画最小工作流（≤5步）
3. 填七区块（每块≤10行，总量80~150行）
4. 写反面案例（2~3条常见错误）
```

### 步骤 1：一句话定义

用这个句式：

> 这个 SKILL 让 **[谁]** 在 **[什么场景下]** 通过 **[什么方式]** 完成 **[什么目标]**

示例：
> 让 **开发者** 在 **PR Review 时** 通过 **静态规则扫描** 完成 **合规风险点识别**

### 步骤 2：画最小工作流

不超过 5 步：
```
接收输入 → 调用服务/执行命令 → 解析结果 → 格式化输出 → (错误处理)
```

### 步骤 3：填七区块

按以下顺序填写 SKILL 文档（含 frontmatter）：

```markdown
---
name: your-skill-name
description: "触发条件描述。当用户说 [触发词] 时使用。| English description"
---

# 技能名称

> 一句话定义

## ① 触发条件（WHO）
## ② 什么时候用（WHEN）
## ③ 执行步骤（WHAT）
## ④ 具体实现（HOW）
## ⑤ 输出格式（FORMAT）
## ⑥ 约束与红线（GUARD）
## ⑦ 关联文档（REF）
## 常见错误
```

**七区块详解**：

| 区块 | 核心内容 | 行数限制 |
|------|---------|---------|
| ① WHO | 触发词/短语列表（3~5个） | ≤5行 |
| ② WHEN | 白名单（应该用）+ 黑名单（不应用） | ≤10行 |
| ③ WHAT | 3~5步最小工作流 + 步骤详解 | ≤30行 |
| ④ HOW | API/CLI/代码实现细节 | ≤15行 |
| ⑤ FORMAT | 正常/拒答/错误三类输出模板 | ≤20行 |
| ⑥ GUARD | 硬性规则 + 决策规则 | ≤10行 |
| ⑦ REF | 关联文档路径 | ≤5行 |

### 步骤 4：写反面案例

每个 SKILL 文档末尾附 2~3 条常见错误：

```markdown
### 错误 N：[错误场景名]
**现象**：[会出什么问题]
**原因**：[为什么犯这个错]
**正确做法**：[应该怎么处理]
```

---

## ④ 具体实现（HOW）

### 文件存放

```
.qoder/skills/{skill-name}/prompt.md
```

### Frontmatter 必填字段

```yaml
---
name: skill-name           # 英文短横线命名
description: "..."         # 触发条件 + 英文描述（双语）
---
```

### description 质量标准

description 直接决定 AI 能否正确触发，必须包含：
- 中文触发词（"当用户说...时使用"）
- 英文补充说明
- 明确的使用场景

---

## ⑤ 输出格式（FORMAT）

### 正常输出

输出完整的 SKILL 文档（Markdown 格式），包含 frontmatter + 七区块 + 反面案例。

### 质量评估

生成后用四维度评分：

| 维度 | 问题 | 满分 |
|------|------|------|
| 可理解 | 另一个人 3 分钟内能看懂吗？ | 3 |
| 可触发 | description 够明确吗？AI 知道何时调用？ | 3 |
| 可执行 | 工作流步骤清楚到可以直接跑吗？ | 3 |
| 有防线 | 红线和反例写了吗？ | 3 |
| **合计** | | **12** |

**≥10 分**：可提交社区  
**7~9 分**：需要打磨  
**<7 分**：建议重写

---

## ⑥ 约束与红线（GUARD）

### 硬性规则

- 总量 **MUST** 控制在 80~150 行，超出说明应拆分为多个 SKILL
- description 字段 **MUST** 包含中英文双语
- 反面案例 **MUST** 至少写 2 条

### 决策规则

1. 不确定区块内容时，先写"TODO"占位，不要留空
2. SKILL 触发词与已有 SKILL 冲突时，增加区分词或调整 WHEN 的黑名单

## 常见错误

### 错误 1：description 太模糊

**现象**：AI 永远不会自动触发这个 SKILL
**原因**：description 写了"通用工具"这种泛泛描述，没有触发词
**正确做法**：明确写出"当用户说 [具体触发词] 时使用本技能"

### 错误 2：工作流超过 5 步

**现象**：SKILL 文档超过 200 行，读起来像一本操作手册
**原因**：把多个职责塞进了一个 SKILL
**正确做法**：拆分为多个 SKILL，每个聚焦一个最小工作流（≤5步）

### 错误 3：没有反面案例

**现象**：SKILL "能用"但不"好用"，边界情况全靠踩坑
**原因**：只写了"怎么做对"，没写"怎么做错"
**正确做法**：至少 2 条反面案例，覆盖最常见的误用场景
